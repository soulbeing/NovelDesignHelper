# 故事织场 · Novel Design Helper

面向小说情节设计的浏览器无限画布。React + TypeScript + Vite，Node.js + Express，React Flow。

## 启动

需要 Node.js **22.12 或以上**。在项目目录运行：

```powershell
yarn install
yarn start
```

打开终端打印的 Vite 地址，默认 **http://localhost:5173**。`yarn start` / `yarn dev` 同时启动前端与 Node API，不需要提前构建。API 默认端口为 3001。若旧服务器正在运行，先在旧终端按 Ctrl+C，再启动。5173 已占用时 Vite 会打印新的前端端口，请以终端为准。

也支持 `npm install`、`npm start`。一个工作目录选择一种包管理器即可。

生产模式：

```powershell
yarn build
yarn serve
```

此时 Node 同时提供构建后的前端与 API，默认访问 **http://localhost:3001**。`serve` 必须先 `build`。

## 第一版能力

- 无限画布：平移、缩放、缩略图、定位全部元素。
- 情节、人物、设定、备注卡片；编辑标题、内容、阶段和故事核心。
- 拖动或依次点击卡片左右连接点创建有方向的关系，点击连线编辑含义。
- 搜索 / 类型筛选、删除、撤销 / 重做（Ctrl/⌘ Z、Ctrl/⌘ Shift Z）。输入框里的快捷键由浏览器处理。
- 修改后自动保存到 Node 服务器的 `data/projects/<项目ID>.json`；浏览器按项目保留本机草稿。未保存到服务器的草稿会提示恢复或下载。
- JSON 导入 / 导出，保留位置和结构；Markdown 导出包含完整内容与带 ID 的方向关系，方便提供给 AI。
- AI 搭档：自带 OpenAI API Key，结合当前故事板聊天，生成结构预览，添加到画布或替换整个故事板，应用后继续编辑或撤销。
- 剧情模板：内置 14 个章内套路和 10 个跨章套路。可先填写角色姓名，再追加人物卡、对话 / 动作节拍或事件阶段、关系和填写提示；整次插入可一次撤销。

首次打开包含可编辑的示例故事「雾港来信」。支持多个独立小说项目；不同浏览器 / 设备连接同一服务器共享项目文件。本地写入检查版本，防止旧页面覆盖新修改；暂不支持账号、自动冲突合并或实时协作。

## 项目、GitHub 存储与版本历史

顶部「项目与版本」（连接后显示同步状态）可打开项目列表、新建作品、连接 GitHub 和查看历史。新建提供空白灵感板、短篇故事、长篇小说、人物关系、悬疑推理五种起始模板；原有「剧情模板」继续用于追加章内/跨章剧情。

创建时填写作品名称、模板、**自己的小说仓库**、分支、作品文件路径和 GitHub Token。推荐 private 仓库；选择 public 则小说内容和历史公开，可见性由用户决定。软件源码仓库不会自动作为小说仓库。默认作品路径为 `projects/<项目ID>/story.json`，改名不改变路径；同一仓库可存多个作品。

使用已初始化的 GitHub 仓库与已有分支，空仓库请先在 GitHub 添加 README。点击「验证仓库」取得默认分支；也可以手动填写。推荐 fine-grained PAT，仅授权小说仓库的 **Contents: Read and write**；Token 的最终写入权限在提交时验证。若分支保护拒绝直接写入，请选择允许写入的小说分支。第一版支持 github.com，不支持 Enterprise 自定义域名。

创建会先保存本地项目，再连接并上传初始版本。连接或上传失败时，本地项目仍保留，可点击「打开已创建的本地作品」，之后在「GitHub 同步」重新连接。打开已有远端作品时输入准确的文件路径，点击「打开仓库里的作品」。已经在当前服务器绑定的作品直接从本地项目列表打开。

- **本地自动保存**：修改后约 700 ms 保存到 Node；浏览器保留恢复草稿。本地保存成功与 GitHub 上传成功分别显示。
- **自动同步**：默认开启；当前作品页面打开且服务器已连接 GitHub 时，每五分钟提交变化内容。不变更不提交。切换后其他作品的待上传版本仍保存在本地，重新打开后可继续同步。
- **保存版本**：「版本历史」填写说明并点击保存，先落盘命名检查点，已连接时立即上传；未连接或网络失败时保留待上传版本，重启后不会丢失。
- **恢复版本**：本地版本和 GitHub 历史均可只读预览、下载 JSON、恢复。恢复前创建当前草稿的检查点，然后把旧内容保存为新版本；不删除提交，不 reset 或 force-push。
- **冲突**：检测小说文件的远端 SHA 变化后停止上传，不覆盖远端。可查看、下载远端副本并导出本地 JSON 后人工整理；第一版不提供自动合并或强制覆盖。要继续创作并发布整理结果，可使用新项目/新路径，原历史保留。
- **凭据**：Token 仅保存在 Node 进程的运行会话；不进入小说、导出、磁盘配置、日志或 GitHub 提交。重启 Node 后重新输入；可在同步面板清除会话 Token。

GitHub 历史是远端 commit 记录，本地目录没有完整 Git 镜像。未上传的命名版本全部保留；已上传版本保留最近 30 份本地副本，完整历史可从 GitHub 按页浏览。API 调用失败时保留本地内容和上传队列。

## 数据格式与兼容性

新导出的作品文件为 JSON：`format: "story-weave"`、`version: 2`、稳定 `projectId` 和现有 v1 `board` 内容。仓库绑定和同步状态仅在本机项目状态文件中；Token 不落盘。应用发行版本与作品格式版本独立。

原 v1 JSON 可继续导入。首次启动新版本时，旧 `data/board.json` 导入固定项目 `legacy-board`，**原文件保持原样**，后续只写多项目存储；重复启动不重复导入。旧 `/api/board` 接口仍读写迁移后的原故事板，避免保留两份互不一致的数据。

磁盘读取、导入、浏览器恢复和 GitHub 历史采用同一兼容解析入口。未知未来版本和未支持字段明确拒绝，原数据保留；支持的额外数据放入文档或 board 的 `extensions` 对象，保存/导出时保留。每次本地状态文件变化原子替换，并保留 `.bak` 上一份状态；若文件损坏，停止覆盖，可停止服务器后用该副本人工恢复。仅读取/预览不改写作品。

长期约束与实施进度见 [AGENTS.md](AGENTS.md) 和 [实施计划](docs/storage-and-github-history-plan.md)。

## 剧情模板

点击左侧「剧情模板」，先选择作用范围，再按类型浏览或搜索。默认打开章内套路，适用于一次对话、一个动作或同一场景的小转折；跨章套路用于铺垫、升级、反转与收束。这是建议尺度，不强制绑定章节数量。

- **章内套路（14 个）**：对话交锋包括顺手一问、答非所问、先退半步、借第三人、玩笑落地、复述关键词；行为互动包括嘴硬手软、借物传情、让出位置、停手半拍、帮完再提；场景转折包括第三人插话、递错物件、一句接不住。每个模板由 3 个短节拍组成，提供句式或动作示例、人物诉求、填写问题与变体，重点是本场的信息、立场或关系发生一点变化。示例应改成角色自己的口吻与习惯。
- **跨章套路（10 个）**：原有借刀杀人、三方争夺、被迫结盟、团队内鬼、误会离间、身份揭露、公开反击和夺宝试炼全部保留；新增宿敌转盟友、人情债。每个模板提供 5 个发展阶段，适合逐步展开的剧情线。

两种尺度可在同一画布组合，例如将章内的“小恩换条件”接入跨章的“人情债”。模板是开放的创作骨架，允许改变节拍、阶段、角色数量、结果与关系。

选择模板后可先填写角色姓名；留空会使用「主角（待命名）」等角色占位。预览展示角色诉求、事件流程、参与者及变体建议。点击「插入画布」后，结构追加在已有内容下方并自动定位，不改变故事名称、故事核心或原卡片。

每位角色生成独立人物卡，每个节拍或事件阶段生成情节卡，并连接人物间的利用、结盟、怀疑等关系。章内卡片以「参与节拍」「引出下一节拍」连接，跨章卡片以「参与事件」「推动下一阶段」连接。作用范围和类型写入卡片阶段与使用提示，随保存、JSON 和 Markdown 导出保留，AI 也能读到。点击卡片，将【占位内容】换成具体事件，回答「待补」问题即可继续细化。同一模板能反复插入，每次都有独立 ID；整次插入作为一个撤销步骤。模板不需要 API Key，也不会调用 AI。

插入时填写的角色名称会写入该次生成的卡片和事件文字。之后修改某张人物卡的名字不会自动替换其他卡片的文字，需要按实际故事编辑。模板生成的内容与普通卡片一样参与保存、JSON 备份、Markdown 导出和 AI 上下文。

## AI 设置

点击顶部「AI 搭档」，填写自己的 OpenAI API Key 和可访问的模型名称（默认 `gpt-5-mini`）。模型需支持 **Responses API + Structured Outputs**。

「讨论故事」只聊天；「生成结构」返回卡片与连线提案。展开提案查看内容后选择「添加到画布」或「替换整个故事板」。生成失败、停止或格式无效都不会修改现有故事。最多一次生成 60 个元素和 180 条关系，服务端等待上限 120 秒；输入较大时建议分段设计。

Key 仅存在页面内存和当次服务器请求，不写入 localStorage、故事文件或日志；刷新页面需要重新填写。聊天记录也仅存在本页面内存。请求固定发送到 `https://api.openai.com/v1/responses`，设置 `store: false`。聊天最近 24 条消息与**整个当前故事板**作为上下文发送至 OpenAI。调用按用户自己的 API 用量计费，需有 API 额度。

默认不开启真实 API 测试，以免消耗用户额度；测试通过模拟 OpenAI 响应验证请求、解析、错误处理和结构校验。

## Windows 与 iOS

Windows 在现代浏览器中使用。iPhone / iPad 使用 Safari；响应式侧栏、底部编辑面板、触摸拖动、双指缩放与点按连线已实现。iPad 横屏更适合大型情节图。尚未在 iOS 真机验证，也尚未实现离线 PWA 或原生安装包。

开发时 Windows 与 iOS 接入同一个 Wi-Fi，在 iOS 打开 `http://<Windows局域网IPv4>:5173`（用 `ipconfig` 查地址，并在 Windows 防火墙中允许对应端口）。手机的 `localhost` 指手机本身。若 Vite 打印了其他端口，请使用那个端口。

当前服务器用于个人本地 / 可信局域网使用，没有登录与租户隔离。部署到公网前需要补上认证和权限控制，并使用 HTTPS；提交 API Key 的设备到服务器链路也应使用 HTTPS。

## 数据与配置

- 服务器数据：`data/projects/<项目ID>.json`、对应 `.bak` 上一份状态，已加入 Git 忽略。原 `data/board.json` 保留作迁移原件。JSON 导出用于额外备份。
- 浏览器本机备份：localStorage，清除浏览器数据会删除该备份。
- 画布上限：1500 个元素、5000 条关系；保存 / 导入请求限制 2 MB。
- 撤销历史仅本次页面会话保留，最多 80 个快照。
- `PORT`：API / 生产端口，默认 3001。开发代理同步采用该值。
- `HOST`：Node 监听地址，默认 `0.0.0.0`。
- `DATA_DIR`：数据目录，默认 `data`。

例如 PowerShell 更换 API 端口：

```powershell
$env:PORT = '3002'
yarn start
```

## 技术选择

Next.js 可以实现此应用，但当前重点是客户端交互画布，服务端渲染不是必要条件。Vite 是构建工具，不是全栈框架；这里采用 React SPA + 独立 Node API，结构直接，适合先把编辑体验做稳。后续确实需要公开页面、复杂路由或服务端渲染时再考虑引入 Next.js。

React Flow 提供可定制节点、连线与触摸交互。当前定位是小说结构编辑器；自由手绘、多种几何图形、图片、分组与结构图图像导出属于后续迭代。

参考：[Next.js SPA](https://nextjs.org/docs/app/guides/single-page-applications)、[React Flow 自定义节点](https://reactflow.dev/learn/customization/custom-nodes)、[OpenAI 结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs)、[GPT-5 mini](https://developers.openai.com/api/docs/models/gpt-5-mini)。
